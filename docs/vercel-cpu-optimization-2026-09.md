# Vercel CPU reduction — September 29, 2026

## Observed usage

The Vercel dashboard showed 6h 32m Fluid Active CPU against the 4h Hobby
allowance, 455,834 function invocations, and 135 GB-hours Fluid memory in its
Last 30 Days view. Build CPU is a separate metric.

The available function breakdown covers only the last 12 hours on this account;
it cannot establish which routes consumed the entire monthly allowance. In the
quiet period inspected, `/api/cron/internal-arenas` was first with 772 invocations
and 27 seconds CPU. `/api/tournaments/live-status` used 8 seconds / 46 invocations,
and `/api/student/online-play` used 3.52 seconds / 79 invocations.

## Changes

1. The existing Supabase cron checks whether Arena maintenance has work before
   invoking Vercel. It retains the one-minute schedule, authorization secret,
   endpoint, timeout and settlement/recovery implementation. The predicate
   covers scheduled starts, overdue endings (including legacy tournaments),
   active v1 tournaments, and finished v1 tournaments without settled results.
   It does not require an online player. A failed result or prize settlement
   keeps maintenance eligible for its next retry.
2. Online-player presence updates can return the fresh player/invitation list in
   the same authenticated response. The client opts in, supports an older
   server, and falls back to reading invitations if presence fails. Authentication,
   no-store responses, student isolation, pending-invitation checks every five
   seconds and normal checks every fifteen seconds remain in place.
3. Concurrent Lichess tournament syncs in one server process share the active
   request. Completed-cache expiry remains unchanged, and a manual forced sync
   can still fetch fresh results after the previous request completes.

No chess engine settings, move validation, game polling intervals, reward rules,
or progress persistence were changed for CPU optimization.

## Expected savings and limits

- Each idle minute avoids one Vercel invocation: up to 1,440 per idle day, or
  43,200 across 30 entirely idle days. Active tournaments retain maintenance.
- Normal online-list polling falls from six to four requests per minute per
  visible student session: approximately 33% fewer requests for this feature.
  Pending-challenge polling falls from fourteen to twelve per minute. Counts
  exclude user actions, focus events, failures and the initial request.
- Simultaneous tournament syncs do one external fetch/parse per process instead
  of one per caller. This is opportunistic deduplication, not a global cache.

These are request reductions, not a promised percentage of total CPU. Existing
quota usage is not erased; savings depend on subsequent traffic and tournament
activity. Normal computer games and browser analysis still use the client engine.
