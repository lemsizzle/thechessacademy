## Reproduced and fixed

The seven original issues below were deployed first. Live WebKit verification
then identified an additional existing issue: Next Link prefetched OAuth start
handlers on the home/login pages, starting redirects without a click and causing
cross-origin access errors. A follow-up uses native document links for
`/api/auth/` routes in `components/Button.tsx`; its browser regression verifies
no request before clicking and exactly one document navigation after clicking.
This does not change OAuth credentials, providers, scopes or account data.

| Issue | Reproduction / consequence | Fix and verification |
| --- | --- | --- |
| Study dialogs clip on short screens | At 844×390, PGN import measured y=-103.5, height=613; Cancel could not be scrolled into view. | Bound five Study dialogs to dynamic viewport height with internal scrolling; tested portrait/landscape, including keyboard opening, Tab containment, Escape and focus return. |
| Study dialog keyboard handling absent | Focus remained behind the import dialog and Escape did nothing. | Reuse the existing game-dialog focus hook in import, completed-game, add-to-study, access and assignment dialogs. |
| Interrupted completed-game import gets stuck | Reject its POST with a network error: uncaught `Failed to fetch`, Add remains “Adding…”. | Catch failure, announce it, clear the busy state and permit retry; disable closure during the mutation. Retry succeeds with synthetic data. |
| Study autosave loses its pending draft on failure | Fail a chapter PATCH: move remains visible but there is no way to retry without editing again. | Retain the newest pending tree, add Retry saving, track failures across chapters and warn on browser unload while saves remain. Browser tests verify both explicit retry and a newer edit after failure. |
| Teacher login fails with full/blocked localStorage | Valid local password yields authenticated server session, but writing the optional legacy marker throws; UI claims login could not be reached. | Make the marker best-effort. Real local server login passes with injected storage failure; server cookie remains authoritative. |
| Hide and Seek Hard Mode loses score recovery | Wrong-square finish receives 503; stars clear, no retry appears and the board reopens for further selections. | Preserve the completed selection, lock the board, stop its timer and show Retry Score. Verify identical request payload on retry and a working fresh round after Play Again. No scoring or reward rules changed. |
| Teacher reward controls overflow a phone | Real `/admin/students` at 390px: cosmetic selector/grid extends to x=412px. | Constrain grid children and form fields so long cosmetic names fit. Test seeded catalog in synthetic admin UI and the rebuilt local route. |

## Re-run locally

Use this isolated checkout, not a production-configured working copy. Existing
dependencies were copied locally; package and lock files are unchanged. Provide
`PLAYWRIGHT_MODULE`, `PLAYWRIGHT_CHROMIUM_EXECUTABLE` and
`PLAYWRIGHT_BROWSERS_PATH` if using browsers installed outside this checkout.

```powershell
npm run lint
npm test -- --maxWorkers=4
npm run build
```

Run each fixture in its own terminal:

```powershell
# Live board fixture on 9417
node scripts/serve-gameplay-harness.mjs

# Area fixture on 9418
$env:GAMEPLAY_FIXTURE='tests/browser/areas-harness.jsx'
$env:GAMEPLAY_PORT='9418'
$env:GAMEPLAY_MOCK_ENGINE='1'
node scripts/serve-gameplay-harness.mjs

# Combined student/admin fixture on 9420
$env:GAMEPLAY_FIXTURE='tests/browser/comprehensive-harness.jsx'
$env:GAMEPLAY_PORT='9420'
$env:GAMEPLAY_MOCK_ENGINE='1'
$env:GAMEPLAY_NAVIGATION='1'
node scripts/serve-gameplay-harness.mjs

# Two-session challenge fixture on 9421; restart before repeated test runs
$env:PORT='9421'
node scripts/serve-online-play-harness.mjs
```

Run the browser scripts above from the checkout. `QA_FIXTURES=studies,rewards`
or `QA_JOURNEYS=trainingVariants` selects a targeted follow-up. Without those
variables the scripts run their whole matrix. The real-app script uses port 9430.
`verify-admin-app.cjs` expects a local server configured with
`ADMIN_PASSWORD=chessquest-local-qa-only` and
`ADMIN_SESSION_SECRET=chessquest-local-qa-session-secret-20261005`, and **no real
Supabase or API keys**. These are disposable fixture values, not account credentials.

## Remaining limits and prioritized improvements

No physical device, real student login/onboarding, live Supabase schema/RLS,
database migrations, real reward ledger, full tournament lifecycle, remote assets,
every bot setting, or full learning curriculum was certified. Those require a
disposable backend with representative test identities and content. Browser
fixture API success must not be interpreted as proof of server authorization or
transactional correctness.

| Priority / size | Improvement | Evidence and expected benefit | Rough effort |
| --- | --- | --- | --- |
| P1, larger | Repeatable disposable Supabase/test-user environment | Current browser coverage is strong at component level but real signed-in student and reward flows are blocked. Enables reliable two-player, tournament, OAuth and XP/coin regression tests without students at risk. | 2–4 days, plus provider test-account setup |
| P1, medium | Durable Study drafts and explicit client-navigation save handling | Failed saves now retry, but pending edits still live in memory. Browser unload warning does not guarantee preservation across every Next client-navigation/back path or device crash. Local draft recovery and a tested leave/save flow would prevent remaining data loss. | 1–3 days |
| P2, quick | Larger Study chapter controls on touch screens | Existing reorder/rename/delete controls use compact `p-1` buttons; browser views show crowded chapter strips. Increase targets and group secondary actions in a menu. | 0.5–1 day |
| P2, quick | Better optional fast-bot feedback/settings | Code intentionally allows up to 45 seconds of thinking, enough to look stuck and exceed old tests. Consider an opt-in fast-reply mode and clearer progress/cancel feedback; retain natural timing where desired. | 0.5–1.5 days |
| P2, medium | Preserve teacher shell with per-section retry during backend outages | With missing local Supabase configuration, dashboard/activity become a full error boundary while other teacher pages remain navigable. A partial dashboard makes teaching work easier to recover. This was reproduced locally, not claimed as a production outage. | 1–2 days |
